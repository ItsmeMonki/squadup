#  SQUADUP: как выложить в интернет

После деплоя приложение открывается по публичной ссылке вида `https://squadup-production.up.railway.app` — с компьютера, телефона и планшета, и ссылку можно отправить друзьям.

В репозитории уже лежит всё нужное: `Dockerfile`, `render.yaml` (Blueprint для Render), `railway.toml` (Railway), `docker-compose.yml` (для VPS/локально).

**Как устроено хранение данных:** SQLite-файл базы. На сервисах без тома файл живёт до перезапуска/редеплоя — и тогда база честно пересобирается из демо-данных (88 анкет, 14 сквадов). Чтобы анкеты и чаты сохранялись, подключи том (`/data`) — как в шагах ниже.

## Шаг 0. Положить код в GitHub (нужно для Railway и Render)

```bash
cd squadup
git init
git add .
git commit -m "SQUADUP — поиск тиммейтов"
```

Создай пустой репозиторий на https://github.com/new (например `squadup`, можно Private) и залей:

```bash
git remote add origin https://github.com/ТВОЙ_НИК/squadup.git
git branch -M main
git push -u origin main
```

> Вариант без GitHub: у Railway есть CLI (`npm i -g @railway/cli`, затем `railway login && railway up`) — тогда шаг 0 не нужен.

---

## Вариант A. Railway (проще всего, ~3 минуты)

1. Зайди на https://railway.com → **New Project → Deploy from GitHub repo** → выбери `squadup`.
2. Railway сам увидит `Dockerfile` и `railway.toml` и начнёт сборку.
3. Сразу добавь том, иначе база не будет сохраняться:
   **Settings → Volumes → Add Volume**, mount path: `/data`.
4. **Variables → New Variable**: `DB_PATH` = `/data/squadup.db` (плюс `PORT` = `8000`, если не подхватился сам).
   После добавления тома и переменной Railway передеплоит сервис.
5. **Settings → Networking → Generate Domain** — получишь публичную ссылку.
6. Проверка: открой `https://ТВОЙ-ДОМЕН/healthz` — должно вернуться `{"ok": true, ...}`.

**Сколько стоит:** есть пробный кредит; дальше план Hobby ~$5/мес (этого хватает с запасом). Том оплачивается отдельно по использованному месту (~1 ГБ бесплатно).

---

## Вариант B. Render (Blueprints, один файл)

1. Зайди на https://dashboard.render.com → **New → Blueprint** → подключи репозиторий `squadup`.
2. Render прочитает `render.yaml` и создаст веб-сервис (Docker, регион Frankfurt) с health-check `/healthz`.
3. Нажми **Apply** — через 2–4 минуты получишь ссылку `https://squadup.onrender.com`.
4. Важно про тарифы:
   - **Free**: сервис засыпает через 15 минут простоя (первый заход после сна ~30–60 сек) и диск не подключается — база будет сбрасываться к демо-данным при рестарте. Для «показать друзьям» этого достаточно.
   - **Starter (~$7/мес)**: не засыпает + можно подключить диск `squadup-data` на `/data` — тогда данные сохраняются (в `render.yaml` диск уже прописан, на бесплатном плане убери блок `disk`).

## Вариант C. Свой VPS (полный контроль, от 3–5 €/мес)

```bash
# на сервере (Ubuntu/Debian), Docker установлен
git clone https://github.com/ТВОЙ_НИК/squadup.git
cd squadup
docker compose up -d --build
# приложение слушает http://IP-СЕРВЕРА:8000
```

Дальше — HTTPS и красивый домен через Caddy (сам получит сертификат Let's Encrypt):

```bash
sudo apt install caddy
sudo tee /etc/caddy/Caddyfile >/dev/null <<'EOF'
squadup.твойдомен.ру {
    reverse_proxy localhost:8000
}
EOF
sudo systemctl reload caddy
```

Обновление версии: `git pull && docker compose up -d --build`.

## Вариант D. Fly.io (если нужен бесплатный старт с томом)

```bash
fly launch --dockerfile Dockerfile --no-deploy
fly volume create squadup_data --size 1 --region fra
fly secrets set DB_PATH=/data/squadup.db
fly deploy
fly open
```

Не забудь в `fly.toml` добавить монтирование тома:
```toml
[mounts]
  source = "squadup_data"
  destination = "/data"
```

## Полезно после деплоя

| Задача | Как |
|---|---|
| Проверить, что сервер жив | `GET /healthz` → `{"ok": true, ...}` |
| Посмотреть логи | Railway/Render → вкладка Logs; на VPS: `docker compose logs -f` |
| Забрать/залить базу | скачать файл из тома (`/data/squadup.db`) — это обычный SQLite-файл, открывается в DB Browser |
| Сбросить всё к демо-данным | удалить файл базы на томе и перезапустить сервис |
| Обновить приложение | `git push` — Railway/Render пересоберут сами (autoDeploy) |
| Ограничить доступ | переменные окружения не дадут многого: для приватной ссылки добавь Basic Auth на уровне платформы или Caddy |

## Вход через Discord (рекомендуется для публичного запуска)

Без настройки приложение работает как раньше — вход по нику. Как только заданы две переменные окружения, в окне входа появляется кнопка **«Войти через Discord»**, а в анкете — блок «Привязанные аккаунты».

**Как получить ключи (5 минут):**

1. Открой https://discord.com/developers/applications → **New Application** → назови `SQUADUP`.
2. Раздел **OAuth2** скопируй **Client ID**, нажми **Reset Secret** и скопируй **Client Secret**.
3. Там же, в **Redirects**, добавь адрес возврата. Локально и в облаке это два разных адреса — добавь оба:
   - `http://localhost:8000/api/auth/discord/callback`
   - `https://ТВОЙ-ПУБЛИЧНЫЙ-ДОМЕН/api/auth/discord/callback`
4. Пропиши переменные на платформе (Railway/Render → Variables, VPS → `.env` для docker compose):

```
DISCORD_CLIENT_ID=123456789012345678
DISCORD_CLIENT_SECRET=xxxxxxxxxxxxxxxxxxxxxxxx
# необязательно — если автоопределение за прокси ошибётся:
DISCORD_REDIRECT_URI=https://ТВОЙ-ПУБЛИЧНЫЙ-ДОМЕН/api/auth/discord/callback
```

5. Перезапусти сервис. Проверка: в окне входа появилась кнопка Discord; вход → в шапке рядом с ником будет метка «● Discord», в анкете — «Discord — привязан».

**Что реализовано:** OAuth2 (scope `identify`), защита от подделки через `state`, привязка Discord к уже существующей анкете (кнопка «Привязать Discord» в «Моей анкете») и отвязка одной кнопкой. Ник берётся из Discord, при совпадении имён добавляется суффикс.

## Уведомления (Web Push) — что нужно на сервере

Уведомления работают «из коробки», но требуют двух условий:

1. **HTTPS** — push не работает по `http://` (кроме `localhost`). На Railway/Render/VPS с Caddy это уже есть.
2. **Библиотека `cryptography`** — уже добавлена в `requirements.txt` и в Dockerfile. Если запускаешь без Docker:
   `pip install -r requirements.txt`. Без неё приложение работает, но кнопка уведомлений скрыта.

VAPID-ключи сервер генерирует сам при первом запуске и хранит в таблице `settings`.
Если хочешь зафиксировать их (например, при переносе базы) — задай переменные:

```
VAPID_PUBLIC_KEY=...   # base64url, 65 байт
VAPID_PRIVATE_KEY=...  # base64url, 32 байта
VAPID_SUBJECT=mailto:admin@твой-домен
```

> Сгенерировать пару вручную: `python3 -c "import webpush; print(webpush.generate_vapid_keys())"`

Проверка: открой приложение → меню профиля → ** Уведомления** → «Включить» → «⏱ Через 30 сек» → закрой приложение.
Уведомление должно прийти с иконкой и текстом. Счётчик на иконке приложения (бейдж) поддерживается на Android/iOS/Windows/macOS.

## Модерация (жалобы и блокировки)

Блокировки и жалобы работают сразу, без настройки: любой игрок может пожаловаться или заблокировать другого из карточки или из чата. Анкета, на которую пришло **3 жалобы** от разных людей, автоматически скрывается из поиска до разбора.

Чтобы модератор мог разбирать жалобы через API, задай переменную окружения:

```bash
ADMIN_KEY=придумай-длинный-случайный-ключ
```

Проверка и разбор:

```bash
# список активных жалоб
curl "https://ТВОЙ-ДОМЕН/api/admin/reports?key=$ADMIN_KEY"

# с историей (включая отклонённые)
curl "https://ТВОЙ-ДОМЕН/api/admin/reports?key=$ADMIN_KEY&status=all"

# решения: dismiss (отклонить), hide (скрыть анкету), restore (вернуть и обнулить счётчик)
curl -X POST https://ТВОЙ-ДОМЕН/api/admin/report-resolve \
  -H 'Content-Type: application/json' \
  -d '{"key":"'"$ADMIN_KEY"'","report_id":12,"decision":"restore"}'
```

Без `ADMIN_KEY` эндпоинты модерации отвечают `403` — если ключ не задан, разбор жалоб просто недоступен, но автоскрытие и блокировки продолжают работать.

**Важно для магазинов:** Google Play требует, чтобы у UGC-приложения были жалобы, блокировки и политика конфиденциальности. Всё три элемента уже есть: `/privacy.html`, кнопки « Жалоба» / « Заблокировать», автоскрытие по жалобам.

## Приложение на телефон (PWA)

Уже встроено: манифест, иконки (обычные + maskable + apple-touch), офлайн-оболочка через service worker (данные всегда из сети, кэшируются только иконки).

- **Android/Chrome/Edge:** открой сайт → меню браузера (⋮) → **«Установить приложение»** (или пункт «SQUADUP» в меню аккаунта внутри приложения).
- **iPhone/Safari:** «Поделиться» → **«На экран „Домой“»**.
- После установки приложение открывается в отдельном окне без адресной строки, с иконкой и тёмной темой.
- В меню профиля есть пункт **« Установить приложение»** — он сам подскажет шаги для твоего браузера.

## Установка на компьютер и телефон

### Windows (проще всего)

1. Нужен Python 3: проверь `python --version` в командной строке. Если нет — поставь с [python.org/downloads](https://www.python.org/downloads/) (галочка **Add python.exe to PATH**).
2. Запусти **`launcher\start.bat`** — сервер поднимется сам и откроется окно приложения.
3. Иконка на рабочем столе и в «Пуск»: правый клик по **`launcher\install-windows-shortcut.ps1`** → «Выполнить с помощью PowerShell».
4. Ещё надёжнее: в открывшемся окне браузера (Chrome/Edge) нажми **⊕ «Установить»** в адресной строке — SQUADUP встанет как обычная программа.

### macOS / Linux

```bash
chmod +x launcher/start.sh launcher/stop.sh
./launcher/start.sh          # откроет окно приложения
```

Иконка в меню приложений (Linux): `cp launcher/squadup.desktop ~/.local/share/applications/` (проверь пути внутри файла).

### Телефон

- **Сейчас, без установки на хостинг:** открой публичную HTTPS-ссылку (см. ниже) в браузере телефона → Android/Chrome: меню ⋮ → «Установить приложение»; iPhone/Safari: «Поделиться» → «На экран „Домой“».
- **Важно:** установить PWA можно только с HTTPS-адреса. По локальной сети (`http://IP-компьютера:8000`) приложение откроется, но иконкой на телефон не встанет — браузеры требуют защищённое соединение.
- **Чтобы приложение на телефоне жило всегда** — выложи его по инструкции ниже (Railway/Render дают постоянный HTTPS-адрес), затем открой этот адрес на телефоне и установи. После установки ссылка больше не важна: приложение остаётся на телефоне.

## Что стоит сделать перед «настоящим» запуском с людьми

1. **Вход.** OAuth Discord уже готов (см. выше) — включи его, и проблема «любой может назваться твоим ником» решается. Следующий уровень: e-mail/пароль или OAuth Steam для подтверждения игровых аккаунтов.
2. **Модерация.** Кнопки «Пожаловаться»/«Заблокировать», автобан по репортам, лог модерации.
3. **База.** SQLite отлично держит десятки-сотни пользователей; при тысячах стоит вынести на PostgreSQL (Railway/Render дают managed-Postgres в один клик).
4. **Приватность.** Политики и согласие на обработку персональных данных (возраст, регион, контакты — это персональные данные), особенно если аудитория в ЕС.
5. **Реалтайм.** Заменить опрос (polling) на SSE/WebSocket — сообщения будут приходить мгновенно.
